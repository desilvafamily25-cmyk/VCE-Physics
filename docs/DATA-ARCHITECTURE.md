# Data Architecture

This app is architected so every read/write goes through the `DataRepository` interface (`src/data/repository.ts`) — components never call `localStorage` or the Supabase client directly, they import `repository` from `src/data/index.ts`. Static, read-only content (papers/interactions/answers/curriculum) is identical for every storage backend and lives in `src/data/staticContent.ts`, shared by both `LocalRepository` and `SupabaseRepository` so only the per-student read/write methods ever differ between them.

**Status: Supabase is connected from day one.** Unlike the sibling VCE Chemistry app (which started localStorage-only and added Supabase later), this app has always required a signed-in Supabase user (`src/auth/AuthGate.tsx`) — `repository` (`src/data/index.ts`) always resolves to `SupabaseRepository`. `LocalRepository` still exists, serving two purposes: (1) it's the read source for the one-time local-progress migration (`src/lib/migrateLocalProgress.ts`) that runs right after a student's first sign-in; (2) it keeps the swap itself proven — both implementations satisfy the exact same `DataRepository` interface.

## Entities

| Entity | Shape | Where it lives today | Notes |
|---|---|---|---|
| **Paper** | id, title, era, pdfUrl, interactionsUrl, formulaSheetUrl, sectionATotal, totalMarks, pageCount, readingMinutes, writingMinutes, hasAnswerData, hasCurriculumMap, hasMultipleChoice | `public/papers.json` (static) | `era` is `current` (2024-2027), `previous` (2017-2023) or `archive` (2002-2016) — drives which curriculum dataset and UI messaging apply. `hasMultipleChoice` is false only for archive-era papers (see below). `readingMinutes` is informational only — by product decision, Timed attempts start writing immediately with no separate Reading Time lock; see `src/lib/timedAttempt.ts`. |
| **Interaction** | id, section, question, page, type, marks, rect | `public/interactions/<paperId>.json` (static) | Absolutely-positioned overlay geometry (0-1 fractions of page width/height) on top of the unmodified exam PDF. `section: "A"` always means auto-gradeable MCQ in this app's type system — VCAA's own "Section A" label means something different for archive-era papers (see below), so archive interactions are always encoded as `section: "B"` regardless of VCAA's own labelling. |
| **QuestionAnswer** | canonicalId (`<paperId>-<interactionId>`), correctAnswer/officialAnswer, marksDistributionPct, examinerComments, difficulty, source, withdrawn? | `public/answers/<paperId>.json` (static) | Generated by the per-year `scripts/extract_<year>_report.py` pipeline from the official examination report; never fabricated. `withdrawn` is a first-class case from day one (see below), not retrofitted. |
| **CurriculumTag** | canonicalId, unit, areaOfStudy, topic, skills[], confidence, uncertain | `public/curriculum/<paperId>-mapping.json` (static) | Editorial mapping against `data/curriculum/study-design-2024-2027.json` (2024+) or `study-design-2016.json` (2017-2023, not yet built). Archive-era papers (2002-2016) are never curriculum-mapped — see below. |
| **Formula sheet** | one PDF per paper | `public/formula-sheets/<paperId>.pdf` | Extracted from the back of that paper's own exam PDF (VCAA appends the era-correct formula sheet to every exam booklet) via `scripts/generate_paper_assets.py`'s `extract_formula_sheet`, not from a single current copy — so a 2018 attempt shows the 2018 sheet, not the 2026 one. Rendered in a toggle-able side drawer (`src/components/FormulaSheetPanel.tsx`) via the same PDF.js pipeline as the exam itself, deliberately outside the graded-interaction layer so referencing it can never be confused with an answer — a consideration the VCE Chemistry sibling app never needed. |
| **Attempt** | paperId, mode ('timed'\|'practice'), answers{}, checked{}, startedAt, lastSavedAt, writingEndsAt (timed only), submittedAt | Postgres `attempts` table (Supabase), RLS-scoped to `auth.uid()` | One row per `(user_id, paper_id)` — `saveAttempt` upserts on that pair. |
| **QuestionResult** | id, canonicalId, paperId, interactionId, section, mode, studentAnswer, outcome, selfAssessed, checkedAt | Postgres `question_results` table (Supabase), RLS-scoped to `auth.uid()` | Append-only — history (not just latest) is kept so "times attempted / times incorrect" in the Error Bank is real. |
| **ErrorRecord** | derived, not stored separately | computed in `src/lib/errorBank.ts` from `QuestionResult` history | Avoids a second source of truth. |

## The archive era (2002-2016) is structurally different, not just older

Confirmed directly off the archive papers' own cover pages, not assumed: pre-2017 VCE Physics has **no multiple-choice section at all**. VCAA's own "Section A" there means compulsory Area-of-Study short-answer questions, and "Section B" means a **pick-one-of-six elective Detailed Study** — a fundamentally different structure from the current/previous designs' 20-MCQ-plus-compulsory-written format. Pre-2013 further splits into two separate sittings (Exam 1 in June, Exam 2 in November), each with its own elective options.

Consequences baked into the type system and data pipeline:
- `Paper.hasMultipleChoice` is `false` for every archive-era paper; `sectionATotal` is `0`.
- Every archive interaction is encoded as `section: "B"` (written), regardless of VCAA's own Section A/B labelling — this app's `section: "A"` always means auto-gradeable MCQ, and archive papers have none.
- Archive papers are never curriculum-mapped against the current study design (their Areas of Study don't correspond) and get Timed/Practice-mode support only, gated by `hasCurriculumMap: false` — matching the build brief's explicit instruction rather than forcing a mapping that wouldn't be honest.

## Structure differs between the two mapped eras too

Confirmed off both eras' own cover pages and the official exam-specifications document (`reference/exam-specifications-v2-2025.docx`), not assumed to match the VCE Chemistry app's numbers:

| | Reading | Writing | Section A | Section B | Total |
|---|---|---|---|---|---|
| Current design (2024-2027) | 15 min | 150 min | 20 MCQ, 20 marks | 100 marks (question count varies by year) | **120** |
| Previous design (2017-2023) | 15 min | 150 min | 20 MCQ, 20 marks | 110 marks | **130** |
| Archive 2013-2016 | 15 min | 150 min | n/a (short answer, ~128 marks) | 1-of-6 elective, 22 marks | **150** |
| Archive 2002-2012 | 15 min | 90 min *(each of 2 sittings)* | n/a | 1-of-3 elective per sitting | **90** *(each sitting)* |

## Withdrawn questions are first-class from day one

VCAA occasionally withdraws a question after the exam (printing error, ambiguity, etc.) — its report row has no correct answer, and a real student's response must never be marked right or wrong. `QuestionOutcome` includes `"withdrawn"` as a value from the start (`src/data/types.ts`), not retrofitted after the fact:
- `isMcqCorrect` (`src/lib/scoring.ts`) returns `false` immediately for a withdrawn question, and `scoreSectionA` excludes withdrawn items from the total entirely — a withdrawn question can never drag a score down or up.
- `McqControl`/`AnswerPanel` render a distinct "Withdrawn" treatment instead of correct/incorrect styling.
- `buildErrorRecords` (`src/lib/errorBank.ts`) skips withdrawn results outright — VCAA withdrawing a question is not the student getting it wrong.
- `report_extraction_lib.py`'s `WITHDRAWN_RE` detects this directly from the report's own prose (e.g. "no longer available"), for both Section A and Section B.
- No withdrawn question exists in the current dataset (2025) — this is a from-day-one design decision, not something driven by an instance already found in the data.

## Auth

`src/auth/AuthContext.tsx` wraps Supabase Auth in a React context. `src/auth/AuthGate.tsx` renders a sign-in/sign-up form when there's no session, and the app otherwise; it fires `migrateLocalProgressIfNeeded` once per user right after a session appears. If the Supabase project has "Confirm email" enabled (the default), `signUp` returns a user with no session — the UI shows "check your email to confirm it, then sign in" rather than silently failing.

## Storage keys (localStorage — pre-account / migration source only)

- `vce-physics.repo.v1.attempt.<paperId>` — current `Attempt`
- `vce-physics.repo.v1.results.<paperId>` — array of `QuestionResult` for that paper
- `vce-physics.repo.v1.migrated.<userId>` — set after migration has run once for that user
- `vce-physics.theme` — light/dark/system UI preference

## Supabase schema

`supabase/schema.sql` creates `public.attempts` (PK `(user_id, paper_id)`) and `public.question_results` (uuid PK, indexed on `(user_id, paper_id)`), both with Row Level Security enabled and policies keyed on `auth.uid() = user_id`. Deployed to its own, separate Supabase project from the VCE Chemistry app (data isolation by design, not shared).

## Repository interface

```ts
interface DataRepository {
  getPapers(): Promise<Paper[]>;
  getInteractions(paper: Paper): Promise<Interaction[]>;
  getAnswers(paper: Paper): Promise<QuestionAnswer[] | null>; // null = not available yet
  getCurriculumMap(paper: Paper): Promise<CurriculumTag[] | null>;
  getSharedStimulusGroups(paper: Paper): Promise<SharedStimulusGroup[]>;
  getAttempt(paperId: string): Promise<Attempt | null>;
  startAttempt(paper: Paper, mode: AttemptMode): Promise<Attempt>;
  saveAttempt(attempt: Attempt): Promise<void>;
  clearAttempt(paperId: string): Promise<void>;
  recordQuestionResult(result: QuestionResult): Promise<void>;
  getQuestionHistory(paperId?: string): Promise<QuestionResult[]>;
}
```

## Difficulty derivation rule

Documented once here, referenced from `scripts/report_extraction_lib.py` and every `data/answers/<paperId>.json`:

> Derived from official cohort performance in the examination report. Section A: percentage of the cohort who chose the correct option. Section B: average mark achieved ÷ marks available. Bands: ratio ≥ 0.70 → Easy, 0.40–0.69 → Medium, 0.20–0.39 → Hard, < 0.20 → Very Hard. `unknown` is used only when no official statistic exists.

No difficulty is ever invented from intuition.

## Extraction pipeline

- `scripts/report_extraction_lib.py` — shared docx-report parsing (Section A results table incl. shading-based correct-answer detection for reports that omit an explicit "Correct answer" column; Section B question/marks-table walking). Deliberately near-identical to the VCE Chemistry app's own library of the same name — same VCAA template family, same technique — with one confirmed wording difference: VCE Physics reports use the singular header **"Mark"**, not Chemistry's plural **"Marks"** (`parse_marks_table` accepts both).
- `scripts/generate_paper_assets.py` — discovers every exam PDF across the three source eras, copies each into `public/papers/`, auto-generates best-effort MCQ/written-field interaction geometry (see `docs/INTERACTION-GEOMETRY-REVIEW.md`), and extracts each paper's own formula sheet.
- `scripts/build_2025_section_b.py` — hand-verifiable Section B geometry for the flagship year, with interaction ids matching the report's own subpart labels (`B11ci`, `B19gii`, ...) rather than a sequential counter, so answers actually join to their on-page control. A small number of subquestions (annotate-a-diagram, fill-in-a-table) have no ruled lines to detect at all and are placed manually, each rect read directly off the source PDF's own figure/table-border coordinates and confirmed by rendering it back onto the page.
- `scripts/build_2025_curriculum_map.py` — maps every one of 2025's 69 interactions to the official study design, built from each question's actual extracted text.
- `scripts/audit_interactions.py` — structural checks across every paper: no Section A ID gaps/duplicates, no rects outside the page, no rects overlapping on the same page, no suspiciously tiny Section B fields (with an explicit per-paper whitelist for verified-correct-but-small manually-placed ones).

## What's deliberately out of scope right now

- Full report extraction + hand-verified interaction geometry + curriculum mapping exists for **2025 only** (the flagship year, built fully end-to-end first per the build sequence). Every other discovered paper (2002-2024, 37 papers total) has auto-generated best-effort interaction geometry and works in Timed Mode; Practice Mode and Topic Practice clearly say data isn't available yet rather than fabricating it (`hasAnswerData`/`hasCurriculumMap` both `false`). Refining those is the next phase, working backward through years as 2025 was done.
- The previous-design study period (2017-2023) needs its own `study-design-2016.json` curriculum dataset before any of those papers can be topic-mapped — not yet built.
